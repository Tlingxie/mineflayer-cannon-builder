# Music camera bot

`scripts/music-follow.js` joins an existing profiled local server as one creative player. It observes the compiled music track's start button and actual powered redstone, then flies along the track. Movement follows confirmed signal updates, so unloaded chunks or a paused server do not advance a wall-clock playback camera. At the end it flies back to the start and waits for another press.

```sh
node scripts/music-follow.js \
  --schematic /absolute/path/to/blueprint.schem \
  --origin 0,64,3456 \
  --host 127.0.0.1 --port 25566 --version 1.21.11 \
  --server-profile /absolute/path/to/server-profile.json \
  --username MusicFollow \
  --state-dir /absolute/path/to/.runtime/music-follow/bird
```

Use a music blueprint generated by this project's MIDI compiler. The server profile must identify the exact running process, FIFO, log, version and endpoint. The command never starts or reconfigures the server. One targeted teleport stages the camera above the start; playback and return use continuous player movement.

Players can opt in through normal in-game chat:

- `!watch`: enter spectator mode and attach the view to `MusicFollow`.
- `!unwatch`: detach and restore the player's original game mode.
- `!music status`: report the camera phase and module index.

The sender's protocol UUID must match exactly one online player. Formatted system messages cannot opt in another player. Before attachment, fresh framed console queries capture the viewer's position, rotation and dimension; these are saved with the original game mode and UUID. Leaving the camera returns the viewer to the saved location and dimension before restoring their game mode. Graceful shutdown restores online viewers and retains recovery records for offline viewers. Reconnecting consenting viewers can reattach. Stop with SIGINT or SIGTERM to restore viewers and disconnect the camera.

`status.json` is replaced atomically every second. `events.jsonl` records signal progress, notes, joins, departures and failures. `process.json` prevents two processes from using one state directory. A disconnected camera retries after five seconds. A profile mismatch prevents console writes. Console operations are limited to targeted camera staging, spectator attachment/detachment and player game-mode restoration.
