# 网页施工控制台

在项目目录运行：

```bash
npm run web
```

浏览器打开 **http://127.0.0.1:3210**。端口被占用时可使用
`npm run web -- --port 3211`。网页只监听本机，不需要额外前端安装或打包。

1. 填写原点 X、Y、Z，选择「蓝图原点」或「包围盒最小角」。Litematica
   蓝图原点与包围盒可能不同，页面会按源坐标换算实际范围。Mk6.1 主炮的真正
   原点三轴必须均能被 16 整除。
2. 拖入 `.litematic` 或 Sponge `.schem` 文件，也可以点击上传。单文件最大
   32 MiB。解析后会显示方块数量、层数、尺寸和俯视预览。
3. 选择 1–30 个 bot，点击「开始施工」。网页显示实际施工报告中的进度、
   当前 Y 层和日志。刷新页面不会停止正在运行的任务。

默认目标固定为 **Minecraft Java 1.21.11，127.0.0.1:25566**。启动施工时
自动核验本机服务器身份并生成外部控制台配置。该服务器需要以 FIFO 接收控制台
输入，并把控制台输出写入普通日志文件；当前已接入的服务器满足此条件。普通
没有这些入口的服务器需要先配置控制台，网页不能绕过游戏权限。

本次施工账号会获得创造模式及 OP 权限，账号名每次不同；任务结束后 OP 记录
保留。bot 仍实际飞到方块附近，通过玩家动作逐块放置。上一层完成并验证后才
进入下一层，自然生成部分沿用现有独立验收。选址应有可点击的基础支撑，并
留出蓝图需要的空地。

同一网页服务只允许一个施工任务。点击「停止施工」后先显示停止中，等待施工
进程和 bot 退出再结束；停止不会撤销已经放置的方块。中断后的高级续建仍使用
命令行 `--resume` 与对应施工记录。

网页不会自行冻结、解冻或重启 Minecraft。需要冻结条件的机构蓝图会在开始
施工前检查，并把缺少的条件显示出来。完整主炮的结构施工不等于发射验收。

上传文件保存在 `.runtime/web/`，详细施工记录在 `.runtime/builds/`；二者
都被 Git 忽略。关闭网页标签不会终止后台服务，在启动服务的终端按 Ctrl+C
会先停止正在施工的 bot，再关闭网页服务。重新启动服务后需要重新上传蓝图。

## 实测记录

2026-10-07，通过网页上传三层 Sponge 蓝图，在 1.21.11 目标服原点
`336,64,256` 使用 6 个 bot 完成 18 个方块。18 次真实放置全部符合
`64 → 65 → 66` 的层屏障，三层最终验证通过；总用时约 27.4 秒，其中
连接与飞行后实际搭建约 1.6 秒。另通过网页验证停止、刷新恢复，以及轨道炮
蓝图解析和非 16 倍数原点阻止开工。此测试不包含完整主炮发射。
