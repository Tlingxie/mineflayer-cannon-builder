# 网页施工控制台

在项目目录运行：

```bash
npm run web
```

浏览器打开 **http://127.0.0.1:3210**。端口被占用时可使用
`npm run web -- --port 3211`。网页只监听本机，不需要额外前端安装或打包。

1. 填写原点 X、Y、Z，选择「蓝图原点」或「包围盒最小角」。Litematica
   蓝图原点与包围盒可能不同，页面会按源坐标换算实际范围。Mk6.1 主炮的真正
   原点三轴必须均能被 16 整除。
2. 拖入 `.litematic`、Sponge `.schem`、`.mid` 或 `.midi` 文件，也可以点击上传。单文件最大
   32 MiB。解析后会显示方块数量、层数、尺寸和俯视预览。
3. 选择 1–30 个 bot，点击「开始施工」。网页显示实际施工报告中的进度、
   当前 Y 层和日志。刷新页面不会停止正在运行的任务。

旧蓝图中的 `minecraft:chain` 在目标版本已改名时会自动识别为
`minecraft:iron_chain`，保留 `axis` 和 `waterlogged` 属性；仍使用旧名称的
版本不转换。此兼容适用于 Litematic 和 Sponge 蓝图，原文件不会改写。

## MIDI 红石音乐轨道

上传 MIDI 后，网页自动把音符和节奏转换成包含音符盒、音色底座、中继器和
起点按钮的 `.schem` 蓝图。检查通过后可先下载生成的蓝图，也可沿用原点与
1–30 个 bot 的设置点击「开始施工」。转换或预览不会启动建造队。

音乐摘要会显示转换后的音符数量、时长、0.1 秒的红石时间量化、最大时间
误差、八度调整数量、重复音符合并数量和所用音色。音符盒的可用音域有限，
超出范围的音高会按八度调整；MIDI 的持续音、力度与原乐器音色不能由单次
音符盒发声完全还原。具体转换限制或不支持的输入会在检查时提示。

bot 实际飞近音符盒放置并设定音高，仍严格自下而上完成每一层。页面会根据
所选原点换算起点按钮的世界坐标；施工后按此按钮播放。较长轨道必须沿轨道
跟随，并保持经过的区块加载，才能连续播放和听到整段音乐。

MIDI 原文件保存在对应上传目录的 `source.mid`，生成蓝图为 `blueprint.schem`。
下载接口只接受已登记的生成蓝图编号；服务重启后需重新上传 MIDI。

支持 Standard MIDI 格式 0/1、PPQ 时间、多轨速度变化、和弦和通道音色；
SMPTE 和格式 2 需要先转换。MIDI 解析限制为 8 MiB、300 秒、100,000 个原始
起音和 200,000 个事件。转换时先做八度调整，再合并相同时间格、音色和音高的
重复音；每个时间格最多 52 个不同音色/音高组合，生成蓝图体积最多 200 万格。
超出限制会提示拆分，不会截断曲目。
遗留文件中的非法 CC7 音量值 255 会被忽略并明确计数提示；其他非法数据
字节仍拒绝，原 MIDI 文件不会改写。
生成的音乐蓝图最终还会检查音符盒音高、底座产生的音色和顶部发声空间。

较长音乐轨道会让 bot 固定负责不同区段，并在每次整层验收前返回各区段的
加载位置。人数不足以覆盖全线时会提示增加 bot。远距离选址会先显示「飞往
工地」，所有 bot 到位并确认区块加载后，才开始最低层；全部区段仍共用同一个
从下到上的层序。导入时会识别并提示旧 MIDI 导出器的 `CC7=255` 音量值，
忽略这些音量设置，保留音符和节拍。

默认目标固定为 **Minecraft Java 1.21.11，127.0.0.1:25566**。启动施工时
自动核验本机服务器身份并生成外部控制台配置。该服务器需要以 FIFO 接收控制台
输入，并把控制台输出写入普通日志文件；当前已接入的服务器满足此条件。普通
没有这些入口的服务器需要先配置控制台，网页不能绕过游戏权限。

本次施工账号会获得创造模式及 OP 权限，账号名每次不同；任务结束后 OP 记录
保留。bot 仍实际飞到方块附近，通过玩家动作逐块放置。上一层完成并验证后才
进入下一层，自然生成部分沿用现有独立验收。选址应有可点击的基础支撑，并
留出蓝图需要的空地。

同一网页服务只允许一个施工任务。点击「停止施工」后先显示停止中，等待施工
进程和 bot 退出再结束；停止不会撤销已经放置的方块。中断后的高级续建仍使用
命令行 `--resume` 与对应施工记录。

网页不会自行冻结、解冻或重启 Minecraft。需要冻结条件的机构蓝图会在开始
施工前检查，并把缺少的条件显示出来。完整主炮的结构施工不等于发射验收。

气泡柱（`bubble_column`）会转换为相同位置的逐层水源放置，再由游戏自然
生成；不会跳过这些位置或把普通水当作最终气泡柱。水桶施工需要冻结世界，
所有主动操作完成后才进入最多 120 秒的自然生成等待。日志出现等待提示后，
需在服务器控制台执行 `tick unfreeze`，程序只继续验收，不会自动解冻。
最终检查仍要求气泡柱方向与蓝图一致。火焰则由 bot 使用打火石在合适底座上点燃。

整图包含尚未支持的实体时会明确拦截施工，目前包括盔甲架（`armor_stand`）。
方块解析或预览成功不代表整张蓝图的实体和机构都能完成。

上传文件保存在 `.runtime/web/`，详细施工记录在 `.runtime/builds/`；二者
都被 Git 忽略。关闭网页标签不会终止后台服务，在启动服务的终端按 Ctrl+C
会先停止正在施工的 bot，再关闭网页服务。重新启动服务后需要重新上传蓝图。

## 实测记录

2026-10-14，在独立 Vanilla 1.21.11 测试服用 3 个 bot 完成 MIDI 生成的
271 方块、5 层轨道，严格层序和全部方块验证通过。两次按按钮均捕获全部
56 个预期音符，包含 52 音和弦；相对起音符合 0/100/200/600/800 毫秒。

2026-10-07，通过网页上传三层 Sponge 蓝图，在 1.21.11 目标服原点
`336,64,256` 使用 6 个 bot 完成 18 个方块。18 次真实放置全部符合
`64 → 65 → 66` 的层屏障，三层最终验证通过；总用时约 27.4 秒，其中
连接与飞行后实际搭建约 1.6 秒。另通过网页验证停止、刷新恢复，以及轨道炮
蓝图解析和非 16 倍数原点阻止开工。此测试不包含完整主炮发射。
